# 第14章　文書を外に出さない構成で、社内のサーバーで運用する

本の第14章を終えた時点のファイルです。本のコードの枠の上の「サンプルコード　ch14/…」は、このフォルダーのファイルを指します。このフォルダーには、それまでの章で使ったファイルもすべて入っています。

この章では、モデルを社内の Ollama に替え、Dify を社内のサーバーに移します。新しく追加・変更したファイルはありません。第8〜13章の DSL ファイルを読み込み直すときは、このフォルダーのファイルを使います。ch08〜ch13 のフォルダーのファイルは、各章で ID を書き込んで上書きしたので、「ナレッジの ID」などの日本語の目印が残っていないためです。

## この章での使い方

コマンドは、Windows は PowerShell、Mac はターミナルで実行します。サンプルコードはホームのフォルダーに `dify-rag-accuracy-samples-main` として展開し、作業用のフォルダー（`sp_sync`・`evaluate`・`report`）もホームのフォルダーに作ってある前提です（[リポジトリのトップ](../README.md)の「フォルダーの置き場所」）。環境変数は、トップの README の「毎回の入力を省く（おすすめ）」のとおりに保存しておくと、PowerShell やターミナルを開き直すたびに設定し直す必要がありません。

1. このフォルダーの `policy_qa.yml` の3か所を書き換えます。ナレッジの ID は、新しいナレッジ「社内規程と手順書（社内のモデル）」の ID にします。チームの ID とチャネルの ID は、第8章と同じ値です。

2. Dify の「スタジオ」の［作成］→［アプリをインポート］で読み込み、名前を「規程の質問に答える（社内のモデル）」に変更します。「答えを作る」の AI モデルを Ollama の qwen3-vl:8b に変更して公開します。

3. 新しいナレッジの ID を `DIFY_DATASET_ID` に設定し、`STATUS` を「有効」にして、点数を測ります。

   Windows（PowerShell）:

   ```text
   cd $HOME\evaluate
   ..\sp_sync\.venv\Scripts\python.exe evaluate.py ..\dify-rag-accuracy-samples-main\data\質問集.csv 結果_第14章_社内.csv
   ```

   Mac（ターミナル）:

   ```text
   cd ~/evaluate
   ../sp_sync/.venv/bin/python evaluate.py ../dify-rag-accuracy-samples-main/data/質問集.csv 結果_第14章_社内.csv
   ```

4. 社内のサーバーに移すときは、第8〜13章の DSL ファイルを、このフォルダーのものから ID を書き換えて読み込みます。毎朝の同期は、`run_sync.ps1`（Mac は `run_sync.sh`）の `DIFY_URL` をサーバーのアドレスに書き換えて続けます。環境変数を保存しているときは、ナレッジの ID や `DIFY_URL` を書き換えた後に、トップの README の「毎回の入力を省く（おすすめ）」のコマンドをもう一度実行します。手順は本の第14章の「社内のサーバーに移す」にあります。

## うまくいったかの確かめ方

- `結果_第14章_社内.csv` の点数を、外のモデルの点数と比べられる

動作しないときは、本の第14章の「うまくいかないとき」を見てください。

第13章から変更したファイルはありません。
