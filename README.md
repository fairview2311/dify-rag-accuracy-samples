# Dify RAG精度改善の教科書 サンプルコード

書籍『Dify RAG精度改善の教科書 SharePoint・Teams連携で社内業務効率化』（早瀬 透）のサンプルコードです。

本では、架空の会社「みどり文具株式会社」の総務部を例に、SharePoint の規程と手順書を Dify のナレッジに取り込み、質問集で点数を測りながら検索の精度を上げていきます。精度を上げたナレッジを使って、規程の質問への回答・問い合わせメールの返信の下書き・申請の確認・規程改定の資料づくり・新人の手順書づくり・毎月の報告を自動化します。

このリポジトリには、次の3種類のファイルが入っています。

- **スクリプト（Python・PowerShell・シェル）** — SharePoint からナレッジへの同期、点数の測定、ID の調査に使います
- **DSL ファイル（`.yml`）** — Dify のアプリの設定を書き出したファイルです。Dify に読み込むと、本のとおりのアプリ（チャットフロー・ワークフロー）ができます
- **サンプルの文書（`data` フォルダー）** — 架空の会社の規程・手順書・過去の問い合わせ・申請と、30 問の質問集です

実在の会社・人物とは関係ありません。

## 動かすのに必要なもの

- Windows 11 か Mac（メモリは 16GB 以上）
- Docker Desktop（Dify を起動するため。本の第2章）
- Microsoft 365 の管理者のアカウント（Entra ID でアプリを登録するため。試用版のテナントでもかまいません）
- OpenAI の API キー（使った量に応じて費用がかかります）
- Python 3.12 以降

第7章では Jina の試用の API キー、第14章では Ollama を使います。取得方法と設定方法は、その章にあります。

## ダウンロードする

このページの上の緑の［Code］を押し、［Download ZIP］を押します。ZIP ファイル（`dify-rag-accuracy-samples-main.zip`）を展開します。Windows はエクスプローラーで右クリックして［すべて展開］を押し、Mac は Finder でダブルクリックします。Windows で、展開先の中にもう1つ同じ名前のフォルダーができたときは、内側のフォルダー（`data` が入っているほう）を使います。

1つのファイルだけを見たい・コピーしたいときは、下の表の章のフォルダーを押し、ファイル名を押して開きます。中身の右上の、四角が2つ重なったボタン（マウスポインターを合わせると「Copy raw file」と表示されます）でコピーできます。

## フォルダーの置き場所

展開した `dify-rag-accuracy-samples-main` フォルダーは、ホームのフォルダーに移動します。ホームのフォルダーは、Windows は `C:\Users\ユーザー名`、Mac は `/Users/ユーザー名` です。本のコマンドは、この場所にあるものとして書いています。

本では、ホームのフォルダーに作業用のフォルダーを3つ作り、このリポジトリから必要なファイルをコピーして使います。

```text
ホームのフォルダー
├── dify-rag-accuracy-samples-main   ← このリポジトリ（展開したもの）
│   ├── ch03 〜 ch14                 ← 章ごとのフォルダー
│   └── data                         ← サンプルの文書と質問集
├── sp_sync                          ← 第3章で作る。sp_sync.py と Python の仮想環境（.venv）
├── evaluate                         ← 第4章で作る。evaluate.py・ask.py
└── report                           ← 第13章で作る。find_ids.py
```

`evaluate` と `report` のスクリプトも、`sp_sync` の仮想環境の Python で実行します（`..\sp_sync\.venv\Scripts\python.exe`、Mac は `../sp_sync/.venv/bin/python`）。パッケージのインストールは、第3章の1回だけです。

## data フォルダー

- **規程** — 年次有給休暇・経費精算・出張旅費など 13 本の Word。改定前の旧版（「旧_」で始まる2本）と、営業部だけの特例を含みます
- **手順** — 申請の手順書とチェックリスト6本（Word と Excel）。紙の申請の時代の旧版を含みます
- **過去の問い合わせ** — 総務部が Teams やメールで受けた問い合わせと答えの記録（CSV）。古い規程のときの答えも残っています
- **申請** — 第10章で規程と照らし合わせる、出張と経費の申請の Excel。SharePoint にはアップロードしません
- **質問集.csv** — 第4章から点数を測るのに使う 30 問の質問集（うち1問は、答えが文書に無い質問）
- **メタデータ.json** — 文書ごとの部署・版・状態（有効・廃止・参考）の一覧。本の手順では使いません（文書の作り方の記録です）

第3章で、「規程」「手順」「過去の問い合わせ」の3つのフォルダーを、Teams の総務部のチームの SharePoint にアップロードします。旧版や古い答えが混ざっているのは、実際の社内の共有フォルダーに近づけるためです。

## スクリプトに渡す値（環境変数）

スクリプトは、Microsoft 365 と Dify の値を環境変数で受け取ります。

- `TENANT_ID`・`CLIENT_ID` — 第2章で登録したアプリのテナント ID とクライアント ID
- `TEAM_ID` — 総務部のチームの ID
- `FOLDERS` — 同期するフォルダーの名前（`規程,手順,過去の問い合わせ`）
- `DIFY_URL` — Dify のアドレス（`http://localhost`）
- `DIFY_DATASET_ID`・`DIFY_API_KEY` — ナレッジの ID と、ナレッジの API キー（`dataset-` で始まる）
- `STATUS` — 第6章から。「有効」にすると、状態が有効の文書だけを検索する
- `DIFY_APP_KEY` — 第8章から。アプリの API キー（`app-` で始まる）

値の調べ方は、本の第3章の「スクリプトに渡す値を調べる」にあります。

### 1回目の同期のとき（本の第3章のとおり）

PowerShell かターミナルで、次のように設定します。`"` の中の日本語を、自分の値に置き換えます（`"` は残します）。この方法で設定した値は、PowerShell やターミナルを閉じると消えます。

Windows（PowerShell）:

```text
$env:TENANT_ID = "テナント ID"
$env:CLIENT_ID = "クライアント ID"
$env:TEAM_ID = "チームの ID"
$env:FOLDERS = "規程,手順,過去の問い合わせ"
$env:DIFY_URL = "http://localhost"
$env:DIFY_DATASET_ID = "ナレッジの ID"
$env:DIFY_API_KEY = "dataset-で始まるキー"
$env:PYTHONIOENCODING = "utf-8"
```

Mac（ターミナル）:

```text
export TENANT_ID="テナント ID"
export CLIENT_ID="クライアント ID"
export TEAM_ID="チームの ID"
export FOLDERS="規程,手順,過去の問い合わせ"
export DIFY_URL="http://localhost"
export DIFY_DATASET_ID="ナレッジの ID"
export DIFY_API_KEY="dataset-で始まるキー"
```

### 毎回の入力を省く（おすすめ）

第3章の「毎朝自動で同期する」で作った `run_sync.ps1`（Mac は `run_sync.sh`）には、7つの値がすでに書かれています。次のコマンドを1回実行すると、その値が自分のユーザーの環境変数として保存され、PowerShell やターミナルを開き直しても残ります。値を打ち直す必要はありません。

Windows（PowerShell）:

```text
Get-Content $HOME\sp_sync\run_sync.ps1 | Where-Object { $_ -match '^\$env:(\w+) = "(.*)"$' } | ForEach-Object { [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], "User") }
```

実行したら、PowerShell をいったん閉じて、開き直します。保存した値は、開き直した後のウィンドウから使えます。`$env:DIFY_URL` と入力して <kbd>Enter</kbd> を押し、`http://localhost` と表示されれば保存できています。

Mac（ターミナル）:

```text
grep '^export' ~/sp_sync/run_sync.sh > ~/sp_sync/env.sh
echo 'source ~/sp_sync/env.sh' >> ~/.zshrc
```

1行目で7つの値を `env.sh` に写し、2行目で、ターミナルを開くたびに `env.sh` を読み込むようにします。2行目は最初の1回だけ実行します。実行したら、ターミナルのウィンドウを新しく開きます。`echo $DIFY_URL` を実行して `http://localhost` と表示されれば保存できています。

第5章と第14章では、新しいナレッジを作り、`run_sync.ps1`（Mac は `run_sync.sh`）のナレッジの ID を書き換えます。書き換えたら、上のコマンドをもう一度実行して（Mac は1行目だけ）、PowerShell かターミナルを開き直します。

`STATUS` と `DIFY_APP_KEY` は、保存されません。使う章で、その章の README のとおりに設定します。`STATUS` は、第6章で空のときと「有効」のときを比べるためです。

保存した値には、Dify の API キーが含まれます。自分だけが使うパソコンで行ってください。保存した値を削除するときは、Windows は `[Environment]::SetEnvironmentVariable("DIFY_API_KEY", $null, "User")` のように名前ごとに実行し、Mac は `~/.zshrc` の `source ~/sp_sync/env.sh` の行を削除します。

## DSL ファイルの使い方（第8〜14章）

DSL ファイルは、Dify に読み込む前に、自分の環境の ID を書き込みます。どの章も、次の順に操作します。

1. DSL ファイルを、テキストエディター（Windows はメモ帳、Mac はテキストエディット）で開く。Mac は［フォーマット］→［標準テキストにする］を押してから書き換える
2. 「ナレッジの ID」などの日本語の目印を、自分の値に書き換えて、UTF-8 のまま上書き保存する
3. Dify の「スタジオ」の［作成］→［アプリをインポート］で読み込む。プラグインのインストールを求められたら、インストールする
4. 編集の画面の右上の［公開する］を押して公開する

書き換える所は、ファイルごとに違います。

- `policy_qa.yml`（第8章）・`revision_notice.yml`（第11章） — ナレッジの ID・チームの ID・チャネルの ID の3か所
- `mail_reply.yml`（第9章）・`expense_check.yml`（第10章）・`onboarding.yml`（第12章） — ナレッジの ID の1か所
- `monthly_report.yml`（第13章） — ファイルの ID・サイトの ID の2か所（`find_ids.py` で調べる）

ID を書き込んで上書きすると、日本語の目印は残りません。同じファイルをもう一度使うとき（第14章で社内のサーバーに移すときなど）は、`ch14` フォルダーの DSL ファイルを使います。`ch14` のファイルは、ID を書き込む前のものです。
