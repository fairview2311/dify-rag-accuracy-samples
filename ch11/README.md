# 第11章　規程改定のお知らせと説明資料を作って送る

本の第11章を終えた時点のファイルです。本のコードの枠の上の「サンプルコード　ch11/…」は、このフォルダーのファイルを指します。このフォルダーには、それまでの章で使ったファイルもすべて入っています。

この章でできるようになること:

- 規程の旧版と新版から、改定のお知らせと説明資料（Word・PowerPoint）を作って、メールと Teams で送れる

## この章での使い方

コマンドは、Windows は PowerShell、Mac はターミナルで実行します。サンプルコードはホームのフォルダーに `dify-rag-accuracy-samples-main` として展開し、作業用のフォルダー（`sp_sync`・`evaluate`・`report`）もホームのフォルダーに作ってある前提です（[リポジトリのトップ](../README.md)の「フォルダーの置き場所」）。環境変数は、トップの README の「毎回の入力を省く（おすすめ）」のとおりに保存しておくと、PowerShell やターミナルを開き直すたびに設定し直す必要がありません。

1. このフォルダーの `revision_notice.yml` を、テキストエディターで開きます。「ナレッジの ID」「チームの ID」「チャネルの ID」の3か所を、第8章と同じ値に書き換えて、UTF-8 のまま上書き保存します。

2. Dify の「スタジオ」の［作成］→［アプリをインポート］で `revision_notice.yml` を読み込み、公開します。OpenAI・Jina・Outlook・Teams・Markdownエクスポーターのプラグインを使います。

3. 練習には、サンプルコードの `data/規程` フォルダーの `旧_経費精算規程_2025年版.docx`（旧版）と `03_経費精算規程_2026年10月改定.docx`（新版）を使います。

## うまくいったかの確かめ方

- Web アプリの結果に、お知らせの文と、Word・PowerPoint のファイルが表示される

動作しないときは、本の第11章の「うまくいかないとき」を見てください。
